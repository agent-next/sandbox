# fpga-agent-loop — spec

Agents design an RV32I CPU in cloud sandboxes and are graded by a judge they cannot talk their way past. Simulation only: no FPGA board is used. Every step runs headless in agent-next sandboxes.

## Goal

1. A **judge kit** (`judge/`) that grades any CPU with the interface below and prints one JSON verdict.
2. Several **designer agents**, each on a different model, each in its own sandbox, write a CPU from this spec alone and iterate against the judge.
3. A **re-grade** of every design in a fresh sandbox with hidden seeds, producing a leaderboard.

## Non-goals

Physical boards, timing sign-off, CSRs/interrupts/privileged ISA, compressed or M extension, caches, performance tuning beyond reporting.

## CPU interface (fixed; same as picorv32's native memory interface)

```verilog
module cpu (
    input  wire        clk,
    input  wire        resetn,      // active-low synchronous reset; PC = 0x0000_0000 after reset
    output reg         mem_valid,   // request; hold until mem_ready
    output reg         mem_instr,   // 1 = instruction fetch (informational)
    input  wire        mem_ready,   // one-cycle acknowledge; may be delayed any number of cycles
    output reg  [31:0] mem_addr,    // word-aligned for fetches; byte address for loads/stores
    output reg  [31:0] mem_wdata,
    output reg  [3:0]  mem_wstrb,   // 0 = read; non-zero = write byte lanes
    input  wire [31:0] mem_rdata,   // valid in the cycle mem_ready is high
    output wire        trap         // 1 on illegal instruction, misaligned access, ECALL or EBREAK; CPU halts
);
```

`output reg` may be `output wire` if the design prefers. One Verilog-2005/SystemVerilog file `cpu.v`, synthesizable (no `initial` blocks except register-file zeroing, no `$display` in synthesized paths, no vendor primitives). Little-endian, flat 64 KiB memory at 0x0000_0000; stores to `0x1000_0000` (tohost) end the test (see below).

ISA: RV32I base (RV32I v2.1 unprivileged spec) minus FENCE.I and CSRs: LUI AUIPC JAL JALR BEQ BNE BLT BGE BLTU BGEU LB LH LW LBU LHU SB SH SW ADDI SLTI SLTIU XORI ORI ANDI SLLI SRLI SRAI ADD SUB SLL SLT SLTU XOR SRL SRA OR AND. FENCE executes as a NOP. ECALL/EBREAK/illegal opcode/misaligned load-store/misaligned jump target assert `trap`.

## Judge (`judge/`, built once, never edited by designers)

Run as `judge/grade.sh path/to/cpu.v [--seed N] [--json out.json]` inside a sandbox; exit 0 only if every gate passes.

| gate | what | pass rule |
|---|---|---|
| G0 lint | `verilator --lint-only -Wall` (warnings allowed, errors not) + yosys `read_verilog; proc; check -assert` | no errors |
| G1 isa | riscv-tests `rv32ui` (all except fence_i), built with a no-CSR `riscv_test.h` whose PASS/FAIL store to tohost (`1` = pass, `(testnum<<1)\|1` = fail) | every test passes |
| G2 diff | random-instruction differential test: Python generator → program; Python ISS gives expected register file + memory signature; the CPU writes its registers to a signature region at the end; compare | 0 mismatches over `--seed`-derived programs (default 200 programs × 500 instructions) |
| G3 trap | directed tests: illegal opcode, ECALL, EBREAK, misaligned LW/SW/jump → `trap` rises, no state change after | all pass |
| G4 bus | the memory model randomizes `mem_ready` latency (0–7 cycles, seeded) during G1–G3 | must pass with random latency |
| G5 synth | yosys `synth_ecp5` + nextpnr-ecp5 `--85k --package CABGA381` with an IO-reducing wrapper | P&R succeeds; report LUT4, FF, Fmax |
| G6 perf | cycles for a fixed benchmark program (bubble sort of 64 words + checksum) under 0-latency memory | report CPI (not a gate) |

Verdict JSON: `{"pass": bool, "gates": {"G0": {...}, ...}, "lut4": int, "ff": int, "fmax_mhz": float, "cpi": float, "seed": int, "tool_versions": {...}}`.

### Judge self-test (`judge/selftest.sh`) — the judge must be shown able to fail

- **Known-good control:** YosysHQ/picorv32 at a pinned SHA, through a thin `cpu` wrapper (ENABLE_COUNTERS=0, CATCH_MISALIGN=1, CATCH_ILLINSN=1, ENABLE_REGS_DUALPORT=1, COMPRESSED_ISA=0, BARREL_SHIFTER=1), must pass G0–G5. ECALL/EBREAK trap behaviour of picorv32 may need the wrapper to map `trap`; document any gate picorv32 cannot pass and why.
- **Known-bad controls:** at least 20 single-edit mutants of the picorv32 core (operator swaps, off-by-one, wrong sign/zero extension, dropped write enable, branch condition flips), generated by a script. Each must fail at least one gate. Report the kill rate; any survivor must be shown equivalent (yosys LEC, `miter -equiv -make_outputs` + `sat -verify -prove trigger 0` after `techmap -autoproc -map +/ecp5/cells_sim.v`) or the judge is strengthened.
- **ISS cross-check:** the Python ISS and picorv32 must agree on 1,000 random programs before the ISS is trusted as G2's oracle.

## Toolchain (pinned, sha256-verified, installed by `judge/setup.sh`)

- YosysHQ OSS CAD Suite release 2026-09-27 (`oss-cad-suite-linux-x64-20260927.tgz`, sha256 `8af3500957e8a304a9bb67ecbcd1e9a7a8bc6ae0813075cc812bfac6143aed86`): yosys, nextpnr-ecp5, ecppack, verilator, iverilog.
- A RISC-V GCC that can target `rv32i/ilp32` (e.g. xPack `riscv-none-elf-gcc` release tarball, or the distro package), pinned to an exact version older than two weeks, sha256 recorded. Prebuilt test images (`.hex`) are committed so grading does not need the compiler; `setup.sh` can rebuild them and the self-test checks they match.
- riscv-tests at a pinned SHA (sources of the `rv32ui` tests only, BSD licence kept).

## Acceptance oracle for this demo

1. `judge/selftest.sh` in a fresh sandbox: picorv32 passes, mutant kill rate ≥ 95 % with every survivor proven equivalent, ISS agrees with picorv32 on 1,000 programs.
2. Each designer's `cpu.v` re-graded by the lead in a fresh sandbox with a seed the designer never saw.
3. Results table (model, pass/fail per gate, LUT4, Fmax, CPI, wall time, tokens if known) in `RESULTS.md`, with logs.
