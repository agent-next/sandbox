# fpga-agent-loop Judge Kit

This directory contains the judge kit for the fpga-agent-loop demo as specified in [SPEC.md](../SPEC.md).

## Contents

- `setup.sh` - Installs the pinned toolchain idempotently into `$HOME/riscv-toolchain` (sha256-verified; `--rebuild-tests` regenerates `tests/*.hex` from source)
- `grade.sh` - Grades a CPU design against gates G0-G6 (all working; G6 reports CPI, not a gate)
- `tb.cpp` - Verilator testbench: 64 KiB RAM, tohost at 0x10000000, trap detection, seeded random `mem_ready` latency 0-7
- `iss.py` - Pure Python RISC-V RV32I Instruction Set Simulator (stdlib only; G2 oracle)
- `gen.py` - Random RV32I program generator (seeded, byte-identical output; used by G2)
- `g2check.py` - G2 driver: runs each generated program on the Verilator DUT and the ISS, compares the x1..x31 signature
- `gen_traps.py` - Generates the directed trap programs in `tests/trap/` (G3)
- `gen_bench.py` - Generates the fixed G6 benchmark `tests/perf/bench.hex` (bubble sort of 64 words + checksum)
- `g6check.py` - G6 driver: runs the benchmark on the Verilator DUT (0-latency) and the ISS, compares the checksum, reports CPI
- `g5_top.v` - IO-reducing synthesis wrapper for G5: `cpu` + internal 16 KiB RAM, 3 pins
- `lec.sh` - Yosys LEC survivor/equivalence checker (SPEC miter+sat recipe, sequential-legal: reset pulse modeled, bounded `-seq 24`)
- `mutants.py` - Single-edit mutants of the fetched picorv32.v for the power test (32 shipped: operator swaps, off-by-ones, sign/zero-extension drops, dropped write-enables, branch flips, decode/trap-targeted); writes to `mutants_out/`
- `riscv_test.h` - No-CSR test header for riscv-tests
- `tests/` - Prebuilt .hex test images (riscv-tests rv32ui, no-CSR build)
- `tests/trap/` - Directed trap programs (generated by `gen_traps.py`)
- `ref/picorv32_cpu.v` - SPEC-interface wrapper around the pinned picorv32 (known-good control)
- `selftest.sh` - Judge self-test (acceptance oracle 1): control grade G0-G5, ISS 1000-program cross-check (`--quick`: 100), all mutants graded with >= 95% kill rate, LEC survivor proofs + LEC power check
- `T1-RECEIPT.md` - Real pasted output for the T1 runs (setup, reference grade, mutant grades)
- `T2-RECEIPT.md` - Real pasted output for the T2 runs (ISS check, G2 on picorv32, 1000-program ISS agreement, G2 power-test mutants)
- `T3-RECEIPT.md` - Real pasted output for the T3 acceptance run (full selftest, kill table, LUT4/FF/Fmax/CPI, LEC proofs)

## Usage

### Setup
```bash
bash setup.sh              # idempotent; sha256-checks every download
bash setup.sh --rebuild-tests   # regenerate tests/*.hex from source
```

### Grade a CPU Design
```bash
bash grade.sh path/to/cpu.v [--seed N] [--json out.json] [--g2-count K]
```
`--g2-count K` shrinks G2 to K random programs (default: the SPEC's 200,
each 500 instructions) for quick iterations.

### Grade a Mutant (power test)
```bash
python3 mutants.py
PICORV32_DIR=$PWD/mutants_out/<name> ./grade.sh ref/picorv32_cpu.v
```

### Run Judge Self-Test
```bash
bash selftest.sh           # full: 1000-program ISS cross-check
bash selftest.sh --quick   # 100-program ISS cross-check
```

## Self-Test

`selftest.sh` (acceptance oracle 1) verifies that the judge can:
1. Pass the known-good control (picorv32 through `ref/picorv32_cpu.v`, gates G0-G5)
2. Cross-check the ISS oracle: `g2check.py` on the gold sim, 1000 random programs (`--quick`: 100), 100% agreement required
3. Kill known-bad controls: all `mutants.py` mutants (32) are graded; >= 95% must fail
4. Prove every survivor input/output equivalent to gold using the SPEC yosys LEC recipe (`lec.sh`)
5. Prove the LEC itself has power: the same recipe run on a KILLED mutant must report NOT EQUIVALENT, else survivor proofs are invalid
