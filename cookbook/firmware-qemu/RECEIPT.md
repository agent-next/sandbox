## Hardening

### Pinned everything

`judge/setup.sh` downloads exactly two artifacts, each from a pinned URL
and each verified by sha256 before use (`sha256sum -c`, hashes above).
No `latest` URLs, nothing auto-resolving. `judge/requirements.txt` is
intentionally empty: the judge uses only the Python standard library.
`judge/VERSIONS.txt` records the `--version` output of every installed
tool; a fresh `setup.sh` regenerates it byte-identically.

Every gate compares against an independent oracle: the toolchain's own
diagnostics (`build_clean`), `readelf` header fields (`elf_ok`), `size`
section totals (`maps_ok`), the QEMU boot banner + scripted
known-answer mask from `judge/spec.json` (`boot`, `shell`), Python

the wire (`no_hardfault`), and before/after sha256 of `judge/`
(`judge_intact`). No gate is "the tool ran".

### Lead findings — disposition and evidence

- **Lead host run recorded**: `run.py --ref sbx/demo-firmware-qemu-2`,
  exit 0; setup 143 s; selftest 119 s; grade 8/8 gates; kill 14/15
  (93 %); sandbox killed and confirmed absent. In the table above.

- **Build-only kills fixed**: the old `crc-init`, `crc-poly`,
  `startup-no-bss`, `startup-no-data` and `build-warning` mutants were
  killed only because the build broke. Re-grading the preserved old
  mutants reproduces the lead's evidence — each verdict shows
  `build_clean: fail "make exited 2"`. All four behavioural mutants were
  rewritten to compile cleanly (the `#define` edits now replace the
  whole line; the two `startup-*` mutants were replaced, see below), and
  every one now dies to `crc_oracle`, `shell` or `boot` — see the kill
  table. `build-broken` is kept as the single deliberate build kill, and
  selftest reports it in its own class.

- **`uart-no-rx` was an equivalent mutant — evidence**: the mutant
  cleared `CTL.RXE` so the UART receiver was "disabled". Graded against
  the old mutant, the verdict is `pass: true` — all 8 gates, including
  `shell: 46/46 exact responses`. QEMU 7.2's pl011 model does not gate
  reception on the RXE control bit (nor TX on UARTEN — the related
  `uart-no-init` mutant still prints its boot banner), so no behavioural
  gate can ever see this fault; it is equivalent by construction and was
  replaced by `uart-rx-inverted` (the RX-FIFO-empty flag tested the
  wrong way), which the `shell` gate kills 46/46.

- **`startup-no-bss` / `startup-no-data` were equivalent too**: besides
  the orphan-`src` build break, QEMU zeroes emulated SRAM at reset and
  the reference firmware's `.data` section is 0 bytes, so neither
  mutation is observable here. Replaced by `startup-no-reset` (reset
  vector → `Default_Handler`) and `startup-bad-sp` (vector slot 0 → 0),
  both killed by `boot`.

- **Missing files added**: `README.md`, this `RECEIPT.md`,
  `judge/VERSIONS.txt`, `judge/requirements.txt`, and the mutant table
  in `SPEC.md` (the standard's `examples/bad/` equivalent — mutants are
  generated by `judge/mutants.py`).
