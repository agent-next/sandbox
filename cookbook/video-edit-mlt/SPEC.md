# SPEC — `cookbook/video-edit-mlt/`

"Premiere, open source": the agent edits a video inside a disposable
agent-next sandbox by writing an **MLT XML timeline** (`edit.mlt`), the
Shotcut `melt` engine renders it, and a judge that measures only the
rendered pixels and PCM — never MLT's own reporting — decides whether the
cut is right.

## Goal

Produce `edit.mlt`, an MLT XML document that renders a fixed edit
decision list (EDL) over three generated source clips with one dissolve,
a logo overlay window, and a ducked music bed, to a hard numeric spec.
The judge renders the timeline itself with `melt` and measures the
output: every output frame's barcode must decode to the (clip, source
frame) the EDL dictates, the dissolve must be a clean 25-frame linear
blend, the logo must sit in the bottom-right corner on exactly frames
0–99, and the audio must hit loudness, true-peak and ducking numbers.

## Fixed problem statement (judge constants — `spec.json`)

| quantity | value |
|---|---|
| container / codecs | MP4, H.264 (`libx264`) video + AAC audio |
| raster | 1280×720, square pixels, progressive |
| frame rate | 25 fps exactly |
| frame count | **225** (9.000 s) |
| audio | 48 kHz stereo |
| clip A segment | output frames 0–99 = clip A source frames 0–99 |
| dissolve | output frames 100–124: linear blend A[src 100+t] → B[src t], t = 0…24 |
| clip B segment | output frames 125–199 = clip B source frames 25–99 |
| clip C segment | output frames 200–224 = clip C source frames 50–74 |
| logo overlay | `assets/logo.png` bottom-right, output frames 0–99 **only** |
| voice windows | t ∈ [1.0 s, 2.0 s) ∪ [5.0 s, 6.0 s) (1 kHz bursts in `voice.wav`) |
| music ducking | 220 Hz band RMS during voice windows ≥ 8 dB below outside them |
| integrated loudness | −16 ± 1 LUFS (EBU R128) |
| true peak | ≤ −1.0 dBTP |

The agent does not choose these; `spec.json` is the contract.

### The sources (`judge/gen_sources.py`, generated by `judge/setup.sh`)

Everything is synthesized deterministically — no downloaded footage:

- `assets/clip_a.mp4`, `clip_b.mp4`, `clip_c.mp4` — 1280×720, 25 fps,
  150 frames each. A flat hue (A red, B green, C blue) is the background
  for moving geometric test shapes. A 16-block barcode at the top encodes `clip_id` and
  the source frame index (4 sync bits `1010`, 2 clip bits, 10 frame
  bits), so any rendered frame names exactly which source frame it came
  from.
- `assets/music.wav` — 9 s stereo 48 kHz, a continuous 220 Hz tone.
- `assets/voice.wav` — 9 s stereo 48 kHz, 1 kHz bursts during exactly
  the two voice windows, silence elsewhere.
- `assets/logo.png` — a 160×80 high-contrast pattern.

Sources are regenerated bit-identically on every setup and checked into
nothing — they are build artifacts (`assets/` is gitignored).

## Non-goals

- No colour grading, effects or titles beyond the logo overlay and the
  one dissolve.
- No claim that MLT is the only way to satisfy the spec — the artifact
  is the XML timeline, and `melt` is the renderer the judge pins.
- No camera footage; the synthetic clips are deliberately machine-
  readable so the judge can verify *every* frame's provenance.
- The judge does not grade code style of the XML, only what it renders.

## Artifact

One file: `edit.mlt` — an MLT XML document that `melt` renders with

```bash
QT_QPA_PLATFORM=offscreen melt -quiet edit.mlt \
    -consumer avformat:out.mp4 vcodec=libx264 acodec=aac \
    crf=18 preset=fast pix_fmt=yuv420p ar=48000 ac=2 \
    threads=1 real_time=-1 movflags=+faststart
```

Only the six relative `assets/` resources are accepted. Absolute paths,
parent traversal, URLs, external XML and non-allowlisted services are
rejected before rendering. The judge copies trusted assets and XML beside
each other in a temporary work directory and sets that directory as MLT's
`root`. The consumer inherits the XML profile: the judge does not override
resolution or fps and thereby hide a bad profile.

## Judge gates (all must pass)

Security, power and format failures stop early. Once format passes, all
pixel/audio gates run even when another measurement fails. `security` and
`integrity` are additional numeric guards (zero unsafe constructs and
zero changed judge files).

`judge/grade.sh <edit.mlt> [--json out.json]`

| gate | numeric pass rule |
|---|---|
| **G1 power check** | The barcode decoder reads **every** frame of the three raw source clips correctly (150/150 each). If it cannot, the judge is broken, not the artifact — fails closed. |
| **G2 format** | ffprobe: `codec_name=h264`, `width=1280`, `height=720`, `r_frame_rate=25/1`, `nb_frames=225` (decoded frame count is what counts); audio `codec_name=aac`, `sample_rate=48000`, `channels=2`. |
| **G3 EDL** | Every output frame outside the dissolve window decodes its barcode to exactly the spec'd (clip, source frame); the flat sampling patch also matches that clip's measured hue within ±16/255 per channel. During the dissolve, all sixteen barcode block means must match the predicted blend of the two specified source frames, maximum normalized residual ≤0.12. An unreadable cut-frame barcode is a mismatch. |
| **G4 dissolve** | Over output frames 100–124 the blend weight `w`, estimated by projecting the centre-region colour onto the A→B axis, is a linear ramp: per-frame `|w_measured − t/24| ≤ 0.20`, `w(100) ≤ 0.15`, `w(124) ≥ 0.85`, non-decreasing within ±0.05 slack. Outside the window every frame's colour is a clean clip hue (enforced by G3's colour check). |
| **G5 logo** | Bottom-right rect template-match score vs `logo.png` ≥ 0.85 on every frame 0–99, and < 0.30 on every frame 100–224. |
| **G6 loudness** | ebur128 integrated loudness −16 ± 1 LUFS; true peak ≤ −1.0 dBTP. |
| **G7 ducking** | 220 Hz RMS, measured by sine/cosine projection over 100 ms windows (exactly 22 cycles), is **≥8 dB lower in each voice window** than outside both windows, with 0.1 s edge guards. Outside music RMS must exceed 1e-5, preventing silence from passing. |

The verdict is one JSON object on stdout with every measured number and
the pass limit per gate; exit 0 only if all gates pass.

## Acceptance oracle (independent of "melt ran")

The judge never asks MLT what it did. It re-derives truth from the
rendered bytes:

1. **Provenance by barcode.** The clips carry their own ground truth —
  a barcode that says which clip and which source frame each pixel band
  came from. Decoding every output frame and comparing against
  `spec.json` catches off-by-one cuts, wrong in-points and reordered
  clips at single-frame resolution. G1 proves the decoder reads the raw
  sources perfectly before it is trusted on the render.
2. **Blend measured, not asserted.** The dissolve is verified by
  projecting the measured pixel colour onto the line between the two
  clip hues — a missing, shortened or non-linear dissolve moves the
  numbers, not the XML.
3. **Logo by template match** against the real `logo.png` pixels, with
  an on/off window checked per frame.
4. **Audio by measurement**: ffmpeg `ebur128` for integrated loudness
  and true peak, and a bandpass+RMS comparison for the ducking depth —
  the same measurements a mastering engineer would make.

## Self-test (`judge/selftest.sh`)

- Unit tests (stdlib `unittest`, `tests/`) for the barcode
  decoder, the blend estimator and the EDL comparator — including one
  that fails if the comparator ignored an off-by-one cut.
- The known-good `examples/good/edit.mlt` passes every gate.
- Every scripted mutant (`judge/mutants.py`, single edits of the good
  timeline) fails, each at its intended gate — target kill rate 100 %:

  | mutant | must die at |
  |---|---|
  | cut moved by one frame | G3 EDL |
  | clip C in-point shifted 10 frames | G3 EDL |
  | clips B and C swapped | G3 EDL |
  | dissolve replaced by a hard cut | G4 |
  | dissolve shortened to 12 frames | G4 |
  | logo moved to the bottom-left | G5 |
  | logo held 25 frames too long | G5 |
  | ducking removed | G7 |
  | master gain +6 dB | G6 |
  | profile 30 fps | G2 |
  | profile 640×360 | G2 |

- Determinism: two grades with the same seed give byte-identical verdict
  JSON outside the `timing` key.
- Judge integrity: `judge/` checksummed before and after grading; the
  artifact is graded from a copy.
- Kill rate below 90 % exits non-zero (the demo's bar is 100 %).

## Judge-integrity rule

The artifact is copied to a temp dir before grading; `grade.sh`
checksums every file under `judge/` (path + sha256) before and after and
fails closed if anything changed. The artifact is XML only — it never
executes judge code.

## Layout

| path | what |
|---|---|
| `judge/gen_sources.py` | deterministic generator for `assets/` (python3 stdlib + pinned ffmpeg) |
| `judge/edl.py` | barcode decoder, blend estimator, EDL comparator (pure stdlib, unit-tested) |
| `judge/grade.py` / `grade.sh` | render + the seven gates, one JSON verdict |
| `judge/mutants.py` | the 11 known-bad timelines as single edits of the good one |
| `tests/` | barcode, blend, EDL, unsafe XML, and run.py fault-injection tests |
| `judge/setup.sh` | pinned Shotcut 26.8.1 + GL libs + generated assets |
| `judge/VERSIONS.txt` | what setup.sh actually installed |
| `examples/good/edit.mlt` | a known-good timeline (written by hand, rendered green) |
| `run.py` | the one-command run |
| `spec.json` | the numeric contract the judge reads |

## Size

225 frames of 720p decoded through ffmpeg crops: a full grade is tens of
seconds on 2 vCPU / ~3 GB RAM; selftest renders the good timeline plus
11 mutants.

## Limits and reproduction tolerances

At a dissolve endpoint a zero-weight source is invisible; no pixel oracle
can prove its identity. In the interior, provenance is measured against
the expected blend with codec tolerance, not recovered as two exact binary
codes. The ramp rule is a tolerance mask, not mathematical equality.

The allowlisted XML subset is deliberately narrower than all of Shotcut.
This validation is not an OS security boundary: render untrusted XML only
inside a disposable sandbox. Trusted setup owns the assets and judge.

Repeat grades must be byte-identical outside `timing`. Across fresh
sandboxes, discrete checks match exactly; audio LUFS/peak tolerance is
0.1 dB, duck depth 0.02 dB, weights/correlations 0.001. Setup supports
x86_64 Linux and CPython 3.12; run.py itself uses stdlib Python 3.10+.
