# SPEC: CFD with OpenFOAM (channel Poiseuille + lid-driven cavity)

## Goal

Demonstrate an agent-next sandbox solving two canonical 2D incompressible
laminar-flow benchmarks with OpenFOAM v1912, installed from pinned,
sha256-checked Debian bookworm packages
(`openfoam` / `libopenfoam` 1912.200626-1+b1, `openfoam-examples` 1912.200626-1).

1. **Plane Poiseuille flow** — steady laminar flow in a unit-square channel
   ([0,1]x[0,1]x[0,0.1]) driven by a fixed parabolic inlet profile with
   U_max = 1 m/s and nu = 0.005 m^2/s, i.e. Re = U_max·h/nu = 100 with
   half-height h = 0.5.
2. **Lid-driven cavity** — unit square, top wall moving at U = 1 m/s,
   nu = 0.01 m^2/s, i.e. Re = U·L/nu = 100.

Both cases use `icoFoam` (transient incompressible, PISO) run to steady
state. Meshes are small (<= 6.4k cells) so a full grade finishes in
minutes on 2 vCPU.

## Non-goals

- Turbulence modelling (RAS/LES), compressible or multiphase flow.
- Parallel (MPI) runs.
- Mesh generation beyond `blockMesh`.
- Solvers other than `icoFoam`.
- OpenFOAM versions other than the pinned Debian packages above.

## Artifact

One OpenFOAM **case directory** per case, containing input files only:

```
<case>/
├── 0/
│   ├── U          # velocity initial field + boundary conditions
│   └── p          # pressure initial field + boundary conditions
├── constant/
│   └── transportProperties   # kinematic viscosity nu
└── system/
    ├── blockMeshDict         # geometry, cell counts, patch names
    ├── controlDict           # start/end time, deltaT, write control
    ├── fvSchemes             # discretisation schemes
    └── fvSolution            # linear solvers, PISO correctors
```

Known-good artifacts live at `examples/good/poiseuille/` (20x20x1 cells)
and `examples/good/cavity/` (40x40x1 cells).  Meshes (`constant/polyMesh`),
time-step results and `postProcessing/` output are generated by the judge
in a scratch copy and are never part of the artifact; `judge/grade.sh`
deletes any shipped results before solving, so a case cannot pass by
committing someone else's output.

`judge/grade.sh <case_dir> [--json out.json]` detects the case type from
the patch names in `blockMeshDict` (`inlet`+`outlet` -> poiseuille,
`movingWall` -> cavity), copies the case to a scratch dir, verifies that
`judge/` is unchanged after the run, and exits 0 only when every gate
passes.

## Gates (numeric pass rules)

### Gate 1 — mesh quality (both cases)
- `blockMesh` exits 0.
- `checkMesh` exits 0, prints `Mesh OK`, max non-orthogonality <= 70 deg,
  max skewness <= 4, zero zero-volume cells.

### Gate 2 — solver convergence (both cases)
- `icoFoam` exits 0 and reaches `endTime`.
- Last-timestep **initial** residuals of `Ux`, `Uy` and `p` are all
  < 1e-5 (the flow is no longer changing per step).
- Last-timestep `global` continuity error < 1e-8.

### Gate 3 — Poiseuille accuracy
- Re consistency: U_max measured on the centreline, nu from
  `transportProperties`; |Re - 100| / 100 <= 0.10.
- Velocity profile: u(y) sampled on the vertical centreline (x = 0.5,
  200 points) vs the analytic solution u(y) = U_max(1 - ((y-h)/h)^2);
  normalised L2 error <= 0.02.
- Pressure drop: least-squares dp/dx over x in [0.2, 0.8] vs the analytic
  gradient -2·nu·U_max/h^2; relative error <= 0.15.

### Gate 4 — Poiseuille mesh convergence
- The judge rebuilds the case at 10x10, 20x20 and 40x40 cells, resampling
  the artifact's own inlet profile onto each mesh, and recomputes the L2
  profile error at each level.
- Observed order log2(e_coarse/e_fine) >= 1.5 on both refinement steps
  (second-order discretisation expected).

### Gate 5 — cavity vs Ghia et al. 1982
- Re consistency: |U_lid·L/nu - 100| / 100 <= 0.10.
- u on the vertical centreline (x = 0.5) and v on the horizontal
  centreline (y = 0.5), sampled at 400 points and interpolated to the 17
  tabulated Ghia stations; max absolute error <= 0.02 (lid-speed units).

## Acceptance oracle

All gates are numeric checks on output the judge produces itself from the
artifact's input files:

- **Gate 3** oracle is the closed-form plane-Poiseuille solution
  u(y) = U_max(1 - ((y-h)/h)^2), dp/dx = -2·nu·U_max/h^2, plus the Re=100
  requirement of this spec (a case tuned to a different Re is wrong even
  though its profile stays parabolic).
- **Gate 4** oracle is the measured convergence rate under refinement.
- **Gate 5** oracle is published reference data: Ghia, U., Ghia, K.N.,
  Shin, C.T. (1982), "High-Re solutions for incompressible flow using the
  Navier-Stokes equations and a multigrid method", J. Comput. Phys.
  48(3), 387-411, Tables I & II (Re = 100, 129x129 grid).

Nothing passes because "the solver ran" — every gate compares a number
against an independent target.
