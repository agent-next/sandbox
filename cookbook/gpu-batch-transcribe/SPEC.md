# SPEC — gpu-batch-transcribe

Batch transcription of air-traffic callsigns from noisy audio, graded by
a judge that the transcriber cannot fool.

## What is simulated

A tower-logs channel: 20 flights each spell their callsign letter by
letter in the ICAO spelling alphabet ("vj731: uniform delta alpha xray").
Each letter is encoded as two 60 ms tone bursts — one at its grid row
frequency (300–800 Hz), one at its column frequency (1000–1600 Hz) — and
sent over a channel with 20 dB signal-to-noise ratio and a random
noise-only lead-in before the push-to-talk click. The agent's job:
write a **batch transcriber** that decodes every utterance's letters back
to text, in one batched pass.

Why a sandbox helps: the decoder is a batched spectral job — every burst
of every utterance is scored against every tone frequency in one
matmul — so the same artifact runs on a plain CPU sandbox or on a GPU
lease (the agent-next REST lease API), and the demo shows both. The
judge runs in a disposable sandbox with a pinned toolchain, and the
transcriber never sees the answer key: it gets the audio and the
signal parameters, not the texts.

## Goal

`judge/grade.sh <artifact>` passes every gate on the known-good
transcriber (`examples/good/transcriber.py`), and the judge kills every
scripted mutant of it.

## Non-goals

- Real speech recognition (phonemes, language models): the channel is
  FSK tones by design, so the decode is a deterministic signal-processing
  problem a small artifact can solve exactly.
- Speed records: the pass rule is accuracy and determinism, not latency.
  Wall time is reported, not gated.
- Speaker identification, audio compression, streaming decode.

## The artifact

One Python file (≤ 128 KiB, stdlib + numpy + torch only) that:

- reads `manifest.json` (grid, tone tables, sample rate) at runtime —
  the redacted manifest the judge hands it has no texts and no ids;
- reads every `utt_<id>.npy` audio file beside it (16 kHz float32);
- decodes each utterance's letters: VAD/onset → 60 ms burst clock →
  batched Goertzel (one complex matmul over all bursts × all
  frequencies) → grid-cell lookup;
- writes `transcripts.json`: `{"transcripts": {<id>: "<token ...>"}}`.

## Judge gates (numeric pass rules)

| gate | rule |
|---|---|
| structure | ≤ 128 KiB; byte-compiles; defines `decode_batch`; reads the manifest at runtime; no `subprocess`/dynamic-import tricks; **no oracle token or seed literal** in the artifact text |
| run | exits 0 on the whole corpus and writes `transcripts.json` within 1800 s |
| shape | every manifest utterance present, non-empty, tokens all in the ICAO grid vocabulary |
| accuracy | exact-match rate ≥ 0.98 **and** oracle WER ≤ 0.02 (edit distance over words) |
| determinism | a second run gives byte-identical `transcripts.json` |
| judge intact | sha256 of `judge/` unchanged after grading |

The artifact is graded from a scratch copy holding only the redacted
manifest + audio; the oracle manifest never leaves `judge/`.

## Self-test (mandatory)

`judge/selftest.sh`: the known-good artifact passes; every scripted
mutant in `judge/mutants.py` fails at least one gate; two grades of the
good artifact give byte-identical verdicts (excluding `timing`);
kill rate ≥ 90 % (it is 100 %: 10/10 mutants killed).

## Acceptance oracle

The corpus is generated by committed, deterministic scripts
(`judge/gen_manifest.py` seeds `random.Random(42)`; `judge/synth_corpus.py`
draws per-utterance noise from `Random(f"{seed}:{id}")` via Box-Muller),
and every audio file's sha256 is pinned in `judge/corpus-sha256.txt`.
`judge/setup.sh` regenerates and verifies the corpus before the judge
runs, so the oracle is fixed by checksum, not by trust in the artifact.

## Reproducibility

- Toolchain pinned: torch 2.14.0 (+cpu wheel, sha256 per CPython version),
  numpy 2.4.3 — `judge/requirements.lock` with `--require-hashes`;
  recorded in `judge/VERSIONS.txt` after install.
- The artifact sets `torch.use_deterministic_algorithms(True)` and runs
  single-threaded BLAS; outputs are byte-identical across runs and
  devices (CPU and CUDA decode the same letters — frequencies and
  magnitudes are far apart, so the argmax never sits on a tie).
- `run.py` clones the repo at `--ref`, installs the judge, and runs
  selftest + grade inside a fresh agent-next sandbox; RECEIPT.md holds
  two fresh-sandbox runs side by side.
