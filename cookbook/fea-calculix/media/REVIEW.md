# Media review — fea-calculix

Date: 2026-10-14. Host: Debian 12 (bookworm), Python 3.12.15,
matplotlib 3.10.7 + numpy 2.2.6 (media/requirements.txt, venv at
media/.venv), ffmpeg 5.1.9-0+deb12u1 (distro), ccx 2.20 / gmsh 4.10.0
(installed by judge/setup.sh).

## Provenance — what is real here

- `data/verdicts/*.json` — written by `judge/grade.sh <artifact>
  --seed 42 --json <file>` on this host: `examples/good` plus the 9
  mutants generated by `judge/mutants.py` into `media/work/mutants/`
  (replayed as a fixing agent's sequence, see loop.png caption — a
  replay of real grade JSONs, not a live agent trace).
- `data/selftest.txt` — real `judge/selftest.sh` output on this host
  (kill rate 9/9, determinism PASS, rc 0).
- `work/<case>/` — real ccx solves. `solve_fields.py` imports
  `judge/judge.py` and calls the judge's own `gen_mesh`, `find_tool`,
  `parse_frd`, `vm_stress`. The deck run is the artifact's `beam.inp`
  with only the output requests widened (`*NODE FILE` / `*EL FILE`
  unrestricted) so the full field can be drawn — same mesh.inc, same
  BCs/loads, same solve. Every case's summary.json cross-checks the
  judge-measured quantities (max -U3 over NTIP, max scaled von Mises
  over NEVAL) against its verdict JSON; all agree to <= 5e-7 relative,
  e.g. good-fine: delta 7.7221 = 7.7221, sigma 138.2409 vs 138.241.
- `data/convergence.json` — tip deflection / wall stress at mesh_size
  and mesh_size/2 parsed from the two real job.frd files; the change
  percentages (0.23 % / 0.50 %) are asserted equal to the good verdict
  JSON's convergence detail before figures are built.

No number in result.png / loop.png / demo.mp4 is invented; the
verification detail strings are parsed out of the verdict JSONs, and
the von Mises field is read from the .frd (judge's own parser), never
recomputed analytically. If a required input file is missing,
make_media.sh / the figure scripts exit non-zero.

  from the same .frd; colour bar carries a red line at the allowable
  166.7 MPa (stated in the colour-bar label). Saturation above
  1.15*allowable is noted on the figure together with the SPEC.md rule

  (deflection 0.23 %, stress 0.50 %, values printed on the bars)
  against the red dashed 2 % gate limit, y range 0..3 %, underlying
  coarse->fine values on the tick labels. Title names the convergence
  gate.
- Panel C: FEA/EB ratios for the reference beam (+0.41 % / -0.74 %)
  inside the +-3 % band; the "0.4016 vs 0.4 mm / +0.41 %" and

## loop.png — checked at full size (2700x1680)

- Top strip: the replayed agent loop (no-stress-output -> undersized ->
  unconverged -> good), y = gates passed (0..3) per that iteration's
  real verdict JSON with a labelled y-axis; points are red unless the
  iteration passed all three gates (green); iteration names are the
  x-tick labels, below the strip title; caption marks it as a replay.
- Matrix: 10 rows (good + 9 mutants) x 3 gates; each cell's text is
  extracted from the verdict JSON detail (PASS cells show the measured
  margin, FAIL cells the measured value vs the limit, e.g.
  undersized/spec_limits "s 465.5 > 166.7 MPa / d 39.01 > 10.00 mm").
  For known-bad rows the failing gate's own metric is what is shown.
  coarse-mesh cells show the validation refusal ("invalid design:
  mesh_size too large"), which is the gate content the judge actually
  emitted — it is killed before any solve.
- fig_loop.py enforces the no-overlap rule in code: after a real
  canvas draw, every cell text's window bbox must sit inside its cell,
  every other placed text inside its axes, and no two registered texts
  (including the strip's tick labels and both titles) may overlap; it
  exits non-zero otherwise.
- Checked: matrix row labels, header gate rules, kill-rate line, and
  replay labels all readable and non-overlapping.

## Deviations / notes

- Kill-pattern detail differs from the pre-hardening lines quoted in
  RECEIPT.md: on this hardened tree `overload-10x` and `propped-tip`
  also trip verification (10x load overloads the reference beam too;
  a clamped tip gives an identically zero field), and `propped-tip`'s
  convergence gate passes trivially (0.00 % — both meshes agree on a
  zero field). Kill rate is unchanged at 9/9. The figures show the real
  per-gate results from the JSONs, which is the point of the matrix.
- The mutant loop shown in loop.png / demo.mp4 is a replay of real
  grade JSONs in a fixing-plausible order, labelled as such on both.
- Colour saturation and the excluded wall-corner singularity are
  explained on result.png itself (SPEC.md measures sigma_wall on NEVAL,
  not at the singular corner).
