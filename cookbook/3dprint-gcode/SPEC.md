# FDM toolpath demo — PrusaSlicer G-code judged by an independent interpreter

## Goal

Show an agent producing a real FDM 3D-print toolpath — a slicer profile plus
G-code from PrusaSlicer — and having a judge it cannot fool decide whether the
result is right.

The agent writes a **slicer profile** (`profile.ini`) and produces
**G-code** (`part.gcode`) by slicing a fixed part STL shipped in the
`task/` directory it is given. The judge is an **independent G-code
interpreter written for this demo** (`judge/interp.py`, Python stdlib only).
It replays the artifact move by move — tracking absolute/relative
positioning (G90/G91), absolute/relative extrusion (M82/M83) and all axis
offsets (G92) — and checks every measured number against an analytic model of
the part STL and the physical print spec. PrusaSlicer's own statistics
(`filament used`, `estimated print time` comments) are only ever used as
cross-checks, never as evidence.

## The task

`task/` holds:

| file | what |
|---|---|
| `bracket.scad` | OpenSCAD source of the part (regenerates the STL exactly) |
| `bracket.stl` | ASCII STL of the part: an L-bracket, bounding box 40 x 20 x 15 mm, ~1.5 mm walls |
| `cube.stl` | 25 mm calibration cube (cross-check oracle only, see below) |
| `spec.json` | the physical print spec, quoted below |

The part STL is generated by `task/make_stl.py` (Python stdlib only, no CAD
dependency) and is deterministic: its sha256 is recorded in this demo's
receipt.

## The artifact the agent produces

The judge grades a **directory** (typically `examples/good/`):

```
<dir>/profile.ini    PrusaSlicer profile bundle or --load-compatible INI
<dir>/part.gcode     G-code for bracket.stl, sliced with that profile
```

The judge runs the slicer itself on `profile.ini`: the artifact's `part.gcode`
must match what PrusaSlicer produces from that profile, and the replayed
G-code is what is graded. An agent cannot hand-craft pretty G-code whose
profile would slice something else, and cannot ship a profile whose actual
output would fail — both are measured.

## Print spec (`task/spec.json`, the contract)

| key | value | meaning |
|---|---|---|
| `filament_diameter_mm` | 1.75 | filament diameter the nozzle is fed |
| `nozzle_diameter_mm` | 0.4 | nozzle orifice |
| `material` | PLA | hotend 180–230 °C, bed 35–70 °C |
| `layer_height_min_mm` / `layer_height_max_mm` | 0.10 / 0.30 | allowed steady layer height band |
| `first_layer_height_mm` | 0.20 +- 0.10 | first layer Z above the bed |
| `max_first_layer_vs_nozzle` | 1.5 | first layer height <= 1.5 x nozzle |
| `bed_size_mm` | [250, 210] | usable bed in X/Y, origin corner |
| `brim_max_mm` | 10.0 | how far outside the part footprint extrusion may go (brim/skirt allowance) |
| `wall_loops_min` | 2 | perimeters/external perimeter count floor |
| `infill_pct_range` | [10, 40] | allowed infill density, per cent |
| `max_filament_g` | 12.0 | deposited filament mass ceiling |
| `max_print_time_s` | 5400 | print time ceiling (90 min) |
| `pla_density_g_cm3` | 1.24 | material density for the mass check |

## Acceptance oracle

Nothing the slicer says about its own output is trusted. Four independent
oracles:

1. **The judge's own G-code interpreter** (`judge/interp.py`) — a from-scratch
   replay of G0/G1/G28/G90/G91/G92/M82/M83/M104/M109/M140/M190 with word
   parsing per the RepRap convention. It measures every quantity the gates
   use: extrusion length from E-word deltas in whichever mode the file
   selects, positions after all offsets, layer Z sequence, temperatures in
   order. The slicer's `; filament used =` / `; estimated printing time`
   comments are parsed only to be *compared against* these measured values.
2. **Analytic STL geometry** — the judge computes the part's volume,
   bounding box and footprint from `bracket.stl` alone (polyhedron volume by
   signed tetrahedra; footprint by segment union of triangle intersections at
   a mid-height Z plane). Expected deposited volume is
   `STL volume x fill`, where `fill = infill + (1 - infill) x f_wall` and
   `f_wall` = the shell fraction of the mid-height slice at the profile's
   extrusion width, computed with `numpy.offset2D` from the measured slice
   polygon. The pass band is +-30 % around that expectation plus a 2.5 cm^3
   ad-hoc allowance for skirt/brim/ooze; the mass ceiling is the hard wall.
3. **The calibration-cube cross-check** — the judge's volume measurement
   must agree with the analytic model on a *known* answer before it can be
   trusted on the artifact: `cube.stl` is sliced with the same profile and
   the judge's deposited volume must land inside the same analytic band.
   This gate fails the judge, not the agent, if the interpreter's arithmetic
   or the band derivation is wrong.
4. **Judge-directory checksums** — sha256 of every file under `judge/` is
   taken before and after grading; any change fails the run.

## Gates

The judge prints exactly one verdict JSON object; exit 0 only if every gate
passes. `P` = measured, `R` = rule.

| # | gate | measured by the interpreter | pass rule |
|---|---|---|---|
| 1 | `slice_clean` | PrusaSlicer exit code slicing `bracket.stl` with `<dir>/profile.ini` | exit 0 **and** non-empty G-code |
| 2 | `artifact_matches_profile` | judge-re-sliced G-code vs `<dir>/part.gcode`, comment lines stripped, whitespace-normalised | identical content hash (proves profile and G-code belong together) |
| 3 | `moves_inside_bed` | every extruding move endpoint and segment | 0 <= x <= 250, 0 <= y <= 210, z >= 0 |
| 4 | `moves_near_part` | every extruding move at z <= 15.6 (part top) | distance from XY point to part footprint <= `brim_max_mm` |
| 5 | `layer_z_sequence` | measured Z of every layer start, first-layer Z | Z strictly increasing (a dip of more than 0.05 mm between extrusion layers fails); first layer Z in [0.10, 0.30] and <= 1.5 x nozzle; every steady layer height in [0.10, 0.30] and <= 0.8 x nozzle |
| 6 | `volume_matches_model` | deposited volume = sum(dE) x pi x (1.75/2)^2 vs STL volume x fill from gate geometry | within analytic band +-30 % and mass <= 12 g |
| 7 | `cube_crosscheck` | same volume measurement on judge-sliced `cube.stl` | inside the cube's analytic band (judge self-consistency) |
| 8 | `pla_temperatures` | M104/M109/M140/M190 set points in order | every nozzle set point in [180, 230] °C before any extrusion that follows it and while it extrudes; every bed set point in [35, 70] °C; first bed heat command precedes first extrusion |
| 9 | `time_estimate_consistent` | interpreter feedrate integration (constant-velocity lower bound) vs slicer's `estimated printing time` comment | interpretation: interpreter estimate >= 0.75 x slicer estimate **and** <= 1.6 x slicer estimate (slicer models acceleration, interpreter does not; band is one-sided-verifiable) and slicer estimate <= `max_print_time_s` |
| 10 | `walls_and_infill_in_profile` | `perimeters`, `fill_density` parsed from `profile.ini` | perimeters >= 2, fill_density within [10 %, 40 %] |
| 11 | `judge_intact` | sha256 over `judge/` before vs after | identical |

Steady layer height is measured between consecutive extrusion-layer Zs,
excluding the first layer (first layer gets its own, looser band).

`grade.sh` takes only `--seed` and `--json`. The seed is recorded in the
verdict; the interpreter and slicer profile are fully deterministic so the
verdict (minus the `timing` key) is byte-identical across same-seed runs.

## Known-bad family

`judge/mutants.py` generates single-edit mutants of `examples/good/`. Each
edits either `profile.ini` (one value) or `part.gcode` (one class of edit)
exactly once. The mutants the self-test runs:

| mutant | edit | gate(s) that must fail |
|---|---|---|
| `filament-diameter-2.85` | `filament_diameter = 2.85` in profile | `volume_matches_model` (deposited volume explodes) — caught via re-slice in gate 2 |
| `petg-temps` | nozzle 240, bed 85 in profile | `pla_temperatures` |
| `layer-height-0.35` | `layer_height = 0.35` on a 0.4 nozzle | `layer_z_sequence` (0.35 > 0.8 x 0.4) |
| `scale-off-bed` | slice with the STL scaled 3x (post-edited G-code translate: X+130 on all moves) | `moves_inside_bed` **and** `moves_near_part` |
| `first-layer-z-zero` | post-edit G-code: first layer `G1 Z0.000` | `layer_z_sequence` |
| `relative-e-mixup` | insert an extra `M82`/`G92 E0` swap mistake: one `M83` block followed by absolute-E values without re-homing E | `volume_matches_model` (interpreter catches the deposit the naive reader misses) |
| `infill-100` | `fill_density = 100` in profile | `volume_matches_model` (mass > 12 g) **and** `walls_and_infill_in_profile` |
| `nozzle-out-of-window` | nozzle temp set to 170 before extrusion | `pla_temperatures` |
| `bed-heats-late` | move first `M140`/`M190` after the first extruding move in G-code | `pla_temperatures` |
| `travel-cuts-part` | drive one extruding move through the middle of the footprint at mid-height, 40 mm beyond the brim allowance | `moves_near_part` |

Every mutant is a one-spot edit from the good artifact; `mutants.py make-all`
writes each as a fresh directory holding a complete `profile.ini` +
`part.gcode`. Mutants that edit the profile are re-sliced by gate 2 itself;
mutants that edit the G-code diverge from the profile and therefore also
fail `artifact_matches_profile`, but each must *additionally* fail the
behavioural gate named in its row — the self-test classifies kills and
requires every behavioural target gate to fire, so renaming the artifact to
hand-pass gate 2 cannot smuggle one through.

## Non-goals

- Not a printer demo: nothing is printed, no motion system, no firmware on
  real hardware. The interpreter validates the toolpath, not the plastic.
- Not a slicer shootout: PrusaSlicer is the only slicer, one version is
  pinned, no tuning advice.
- No acceleration/jerk model, no pressure advance, no cooling model: the
  time gate is a constant-velocity integration cross-checked against the
  slicer's own (acceleration-aware) estimate with a stated band, not a
  physical prediction.
- Supports, multi-material, sequential printing, mesh booleans, procedural
  slicing modifiers are all out of scope.
- The judge is not a security boundary: `grade.sh` runs the slicer with the
  artifact's profile, so a hostile profile that injects a post-processing
  script could influence the verdict. Grade untrusted artifacts in a
  disposable sandbox.

## What this demo does not prove

- That the part would print well: layer adhesion, warping, ringing,
  stringing and surface quality are physics the interpreter does not model.
- That PrusaSlicer is right: the judge can only catch paths that violate
  the numeric spec; a subtly bad but in-spec path passes.
- Anything about nozzle wear, filament moisture, or machine calibration.

## Tolerances for reproduction

- Verdict JSON minus `timing` must be byte-identical across same-seed runs
  on any amd64 Debian 12 host with the pinned toolchain.
- `deposited_volume_mm3` and `stl_volume_mm3` must match a reproduction run
  exactly (both are deterministic sums over the same inputs).
- Wall-clock fields under `timing` drift; nothing else may.
