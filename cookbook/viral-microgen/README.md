# viral-microgen — the "internet package" factory

A single prompt turns into a verified folder of shareable media: a Shepard
tone WAV that rises forever and returns to the pitch class it started on, a
bouncing-ball GIF, a QR code that really scans, and a 5-colour palette card
sampled from the GIF. A sandbox helps because the four artifacts need four
different toolchains — audio synthesis, an animated-GIF encoder, a QR
encoder, and two independent QR *decoders* (zbar and zxing-cpp) that must
agree — and none of it should touch your machine. The sandbox is disposable:
it is created, does the work, and is killed at the end of the run.

The judge never reports "the tool ran". Every gate compares against an
independent oracle: an analytic octave model for the tone, frame geometry for
the bounce, two pinned reference decoders for the QR, and exact RGB set
equality for the palette.

## Ask your agent

> In a sandbox, clone the repo and run the viral-microgen demo end to end:
> build the artifact folder (Shepard WAV, bouncing-ball GIF, QR code,
> palette card) with `tools/make_artifact.py`, then grade it with
> `judge/grade.sh`. Show me the verdict JSON and every number the judge
> measured. If a gate fails, fix the artifact and re-grade until all six
> gates pass.

## One-command run

```bash
pip install "git+https://github.com/agent-next/sandbox#subdirectory=cli"
export SBX_API_KEY=<your key>
python3 cookbook/viral-microgen/run.py --ref main
```

`run.py` creates a sandbox, clones the repo at `--ref`, installs the pinned
tools, runs the judge self-test, grades the known-good artifact, prints the
verdict and a summary, then kills the sandbox and confirms it is gone.
`--keep` leaves the sandbox up and prints its id; `--seed N` changes the
planted QR string (the judge expects `VIRAL-MICROGEN-<N>`).

Exit codes: 0 only when setup, the self-test and the grade all pass; 1 on any
failure, naming the sandbox id if cleanup could not be confirmed.

## The gates

`judge/grade.sh <artifact_dir> [--seed N] [--json out.json]` prints one JSON
verdict and exits 0 only if all six gates pass:

| gate | oracle | key numbers from `examples/good` |
|---|---|---|
| `wav_format` | stdlib `wave` header parse | 22050 Hz mono 16-bit, 22.0 s |
| `shepard_property` | analytic fit to the measured chroma glide | span 3.9998 oct, R²=0.999998, returns 3.9998 oct |
| `gif_animation` | Pillow frame walk | 60 frames, 5 colours, loop=0 |
| `ball_bounces` | ball-mask geometry per frame | 7 bounces, rise 213 px, travel 172 px |
| `qr_scans` | zbar 0.23.92 **and** zxing-cpp 2.3.0 | both return `VIRAL-MICROGEN-42` |
| `palette_match` | exact RGB set equality with the GIF | 5 swatches, exact match |

The self-test is the part that proves the judge can fail: `judge/selftest.sh`
grades the known-good artifact, then 15 single-edit mutants (including the
required negative controls — a 1-frame static GIF and a QR encoding the wrong
string), and requires every mutant to be killed by the gate it is aimed at,
with a kill rate of at least 90 %.

```bash
python3 tools/make_artifact.py examples/good --seed 42   # regenerate the good artifact
bash judge/selftest.sh                                   # 15/15 killed, 100 %
```

## Limits, stated plainly

- The artifacts are synthetic by construction, not a study of human
  perception: the WAV is a *model* of the Shepard illusion and the judge
  measures the model (a chroma glide that rises a whole number of octaves),
  not whether a listener hears an endlessly rising tone.
- The GIF is a 480×270 ball, a floor and nothing else; the palette card is an
  exact re-statement of the GIF's five colours, not a perceptual quantisation.
- `examples/good/` is generated by `tools/make_artifact.py --seed 42`; it is
  deterministic, so the file hashes in `RECEIPT.md` are stable, but changing
  the generator changes the example.
- The QR encoder is the demo's own standard-library implementation
  (`tools/qr.py`); its correctness is *established* by the two pinned
  reference decoders in the `qr_scans` gate rather than assumed.
- `judge/setup.sh` needs `sudo` for the two zbar Debian packages; the
  zxing-cpp wheel and the Python dependencies go into a private venv under
  `$HOME` and need no privileges.

See `SPEC.md` for the goal, non-goals and the full numeric pass rules, and
`RECEIPT.md` for the raw output of two fresh sandbox runs.
