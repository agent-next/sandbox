# viral-microgen — the "internet package" factory — spec

## Goal

Prove that an agent can, inside one disposable sandbox, turn a single prompt
into a verified folder of shareable media: a Shepard-tone WAV that rises
forever, a bouncing-ball GIF, a QR code that really scans, and a 5-colour
palette card sampled from the GIF. Every artifact is checked by gates with
numeric pass rules against an **independent oracle** — the judge never merely
reports "the tool ran".

The factory produces **one artifact directory**:

```
artifact/
  shepard.wav    mono 16-bit PCM, >= 20 s, rises forever, returns to its pitch class
  ball.gif       animated GIF, >= 48 frames, 5-colour, a ball bouncing on a floor
  qr.png         QR code encoding the planted string for the grading seed
  palette.png    5-colour palette card: exactly the colours used in ball.gif
```

## Fixed problem statement (judge constants)

| quantity | value |
|---|---|
| sample rate (WAV) | 22050 Hz, mono, 16-bit PCM |
| minimum WAV duration | 20.0 s |
| Shepard octave rise | >= 3.0 octaves spanned over the file |
| Shepard pitch-class return | `f_end >= f_start * 0.95` and `log2(f_end/f_start)` an octave multiple within 0.020 oct (judge constant `OCTAVE_TOL_OCT`) — the tone ends on the pitch class it started on |
| GIF frame count | >= 48 |
| GIF distinct colours | exactly 5 |
| GIF ball bounces | >= 4 |
| QR planted string (`--seed N`) | `VIRAL-MICROGEN-<N>` (judge-side constant) |
| QR decoders | zbar 0.23.92 **and** zxing-cpp 1.4.0 (two independent libraries) |
| palette colours | exactly 5, each an exact RGB match to a colour present in the GIF |

The planted QR string is derived from `--seed` inside the judge, so the seed
is a real knob: `grade.sh --seed 42` expects `VIRAL-MICROGEN-42`.
`tools/make_artifact.py --seed 42` regenerates the good example byte-for-byte.

## Non-goals

- audio/video encoding choices beyond the ones pinned above (no mp3, no mp4,
  no transparency in the GIF, no interlacing)
- any artwork, text, or branding inside the artifacts: the GIF is a ball, a
  floor and nothing else
- mass colour work: the GIF is limited to 5 colours by construction, so the
  palette card is an exact re-statement of the GIF's colour set, not a
  perceptual quantisation
- third-party data of any kind: every input is generated by a seeded script
  in this directory (`tools/make_artifact.py`), so there are no URLs or
  licences to cite

## Artifact contract

A directory containing the four files above. Nothing else is required; a
file the judge does not know about is ignored. The four files are read-only
inputs to the judge.

## Judge gates (all must pass)

Every gate is numeric and deterministic; grading twice with the same `--seed`
on the same artifact gives byte-identical verdict JSON except the `timing`
key.

1. **wav_format** — the file parses as RIFF/WAVE via the standard-library
   `wave` module; mono, 2-byte sampwidth, framerate 22050 Hz, and
   `nframes/22050 >= 20.0 s`. Any structural failure fails the gate (a file
   that cannot be parsed is not a WAV).
2. **shepard_property** — the oracle is an analytic fit to the measured
   chroma trajectory.  A Shepard tone's partials are octave-spaced, so they
   all sit at the same chroma `r(t) mod 1`; the judge measures that chroma
   and fits a line to it:
   - per 4096-sample Hann-windowed frame (1024-sample hop), the power
     spectrum's log2 frequencies are folded modulo one octave (reference
     40 Hz) onto a 180-bin circular histogram, and the chroma is the
     power-weighted circular mean of the bins around the peak;
   - the folded chroma is unwrapped into a rising trajectory `r(t_i)` and
     least-squares fitted: the trajectory must be rising (`slope > 0`),
     linear in the fitted sense (`R^2 >= 0.995`), and span
     `r(t_end) - r(0) >= 3.0` octaves, so the tone genuinely "rises forever";
   - the Shepard identity: the fitted glide at the file boundaries spans an
     integer number of octaves within `0.020 oct` (`OCTAVE_TOL_OCT`), so
     after rising through the octave stack the tone ends on the pitch class
     it started on (this is the property a plain steady tone or a plain
     sweep fails);
   - the spectrum of the whole file must show the Shepard signature: split into
     8 neighbour octave bands, the band energies must be unimodal with the
     maximum in one of the middle bands (2..6), and
     `mid_energy/tail_energy >= 8` (dB), which a monotone sweep does not have.
3. **gif_animation** — the GIF decodes with Pillow; `n_frames >= 48`; every
   frame has a positive duration and the same size; the declared loop count is
   infinite (`loop == 0`); every frame uses exactly the same 5-colour palette
   and no frame introduces a sixth colour.
4. **ball_bounces** — the oracle is geometry. Per frame the judge isolates the
   ball pixels (the frame colour that is neither the floor colour nor the
   background colour: with exactly 5 colours it picks the colour whose pixels
   are connected and roundest, judged by area/perimeter), and needs
   `n_bounces >= 4` local maxima of the ball's bottom edge in image
   coordinates, plus: the ball's bottom row at each bounce is within 2 px of a
   single constant floor row, the ball rises at least 25 px above the floor row
   between bounces, and the ball travels >= 120 px horizontally across the
   file. A single frame fails this gate outright (that is the negative control).
5. **qr_scans** — `qr.png` decodes to exactly `VIRAL-MICROGEN-<N>` under
   zbar 0.23.92 (`zbarimg --raw`) **and** under zxing-cpp 1.4.0
   (`read_barcode`); a single decode is not enough. Both must agree on the
   exact string; a wrong string, or a QR only one library can read, fails.
6. **palette_match** — `palette.png` parses with Pillow; it has exactly 5
   swatch regions of equal size on a solid background; each swatch's RGB
   value is an **exact** match (`R,G,B` all equal) for a colour that occurs in
   the GIF frames at least 50 times; and the set of the 5 swatch colours is
   exactly the set of distinct colours present in the GIF. A colour invented
   for the card, or a GIF colour missing from the card, fails.

Gate names in the verdict JSON: `wav_format`, `shepard_property`,
`gif_animation`, `ball_bounces`, `qr_scans`, `palette_match`.

## Acceptance oracle

| gate | oracle |
|---|---|
| `wav_format` | stdlib `wave` header parse + declared sample-rate arithmetic |
| `shepard_property` | analytic octave model: log-linear fit of the measured pitch trajectory + band-energy envelope test |
| `gif_animation` | Pillow frame walk; frame count/size/duration/palette equality |
| `ball_bounces` | geometric analysis of the ball mask per frame (bounce count, floor-row constancy, apex height, horizontal travel) |
| `qr_scans` | two independent QR reference libraries, both pinned by version |
| `palette_match` | exact RGB set equality between the card's swatches and the GIF's distinct frame pixels |

Validation happens before any gate runs: a missing file, a directory instead
of a file, or an empty file fails every gate with that reason (a malformed
artifact must never be reported as a partial pass).

## Self-test

`judge/mutants.py` writes scripted single-edit mutants of
`examples/good`; the known-bad set includes the required negative controls
(a 1-frame static GIF and a QR encoding the wrong string) plus mutants of the
WAV (steady tone, non-returning sweep, too short), the GIF (too few frames,
six colours, flat ball that never bounces), and the palette (a colour not in
the GIF, a GIF colour missing). `judge/selftest.sh` requires the good artifact
to pass, `killed/total >= 90 %`, and two `--seed 42` grades of the good
artifact to be byte-identical except `timing`. Each mutant and the gate that
kills it is listed in `examples/bad/README.md`.
