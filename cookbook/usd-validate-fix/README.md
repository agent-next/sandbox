# usd-validate-fix — repair an OpenUSD asset a judge can't fool

An agent has to *fix geometry data*, not just run a tool: the task is a
script-generated road-traffic-cone prop (three meshes, two materials, a
physics collider, authored in centimetres) seeded with six realistic DCC
export defects — no normals, wrong `metersPerUnit`/`upAxis`, a degenerate
zero-area face, an unbound material, no `defaultPrim`, no authored
extents. The artifact is the repaired `.usda`. The judge is NVIDIA's
`nvidia_usd_validate` at a pinned release **plus** an independent oracle
built only on pip `usd-core` that re-derives every property from scratch
and a geometry-invariance gate against the original asset — a "fix" that
deletes the offending mesh or scales the points by 100 to fake the unit
fails. A disposable sandbox is the right place for this: the agent needs
OpenUSD, the validator and a throwaway filesystem to iterate repairs in,
and the graded artifact is one small file it hands back.

## Results

Key numbers from the judge verdict (`examples/good/traffic_cone_fixed
.usda`, usd-core 25.5 + usd-validation-nvidia 1.22.0 on Python 3.12):

- **NVIDIA validator**: `PASS`, 0 FAILURE / 0 ERROR issues (gate 1)
- **Oracle recount**: normals == face corners on all 3 meshes (24 / 60 /
  40), all unit-length within 1.7e-08, 0 zero-area faces, 3/3 bound
  materials, 1 collider, extents authored (gate 2)
- **Geometry preserved**: 3/3 mesh paths, point counts 8 / 20 / 20, bbox
  deviation 0 cm vs the original within 1e-06 (gate 3)
- **Self-test kill rate**: 11/11 = 100 % (requirement ≥ 90 %)

## Ask your agent

> Set up a sandbox and solve the demo in `cookbook/usd-validate-fix/` of
> https://github.com/agent-next/sandbox (clone it first). Run
> `bash cookbook/usd-validate-fix/judge/setup.sh`, read
> `cookbook/usd-validate-fix/SPEC.md`, then repair the asset yourself:
> start from `cookbook/usd-validate-fix/task/traffic_cone_broken.usda`
> and write a fixed `.usda` that keeps the three meshes at
> `/TrafficCone/Base`, `/TrafficCone/Body` and `/TrafficCone/Band` with
> their point arrays unchanged, and gives the stage
> `metersPerUnit = 0.01`, `upAxis = "Y"`, `defaultPrim = "TrafficCone"`,
> face-varying unit normals (one per face-corner), a correct `extent`
> per mesh, a material binding on every mesh (Band → the white plastic,
> others → the orange) and the physics collider kept. Iterate with
> `bash cookbook/usd-validate-fix/judge/grade.sh <your-fixed.usda> --json v.json`
> until it exits 0, then paste the final verdict JSON. Do not edit
> anything under `judge/`; if you believe the judge is wrong, say so
> instead of working around it. Kill the sandbox when you are done.

The known-good example in `examples/good/` was generated by
`task/make_task.py`; a working answer does not have to match it, only
the SPEC gates.

## One-command run

```bash
pip install "git+https://github.com/agent-next/sandbox#subdirectory=cli"
export SBX_API_KEY=<your key>
python3 cookbook/usd-validate-fix/run.py          # --ref main --keep supported
```

Creates a sandbox, clones the repo, installs pinned tools, runs the judge
self-test, grades `examples/good/traffic_cone_fixed.usda`, prints the
verdict JSON, then kills the sandbox and confirms it is gone. Stdlib
only; exits non-zero on any failure, naming the sandbox id if cleanup
could not be confirmed.

## Measured wall time (Debian sandbox, 2 vCPU)

| step | wall time |
|---|---|
| `git clone --depth 1` | ~2 s |
| `judge/setup.sh` (fresh venv + pinned wheels) | 36 s (idempotent re-run: 2 s) |
| `judge/selftest.sh` (good + 11 mutants + determinism) | 52 s |
| `judge/grade.sh examples/good/traffic_cone_fixed.usda` | 8 s |

Whole run, including sandbox create and kill: a few minutes; grading
itself is seconds. `run.py` prints a per-step timing line.

## Limits, plainly

- Python 3.10–3.12 only: the pinned `usd-core==25.5` wheels ship no
  cp313+ ABI, and the validator's rule set needs OpenUSD ≥ 22.11.
- Gate 1 disables exactly one rule, `MaterialUsdPreviewSurfaceChecker`:
  pip `usd-core` ships no `shaderDefs.usda`, so the Sdr registry resolves
  no shader id for *any* asset and the rule can only report that
  environment warning. Everything else in the default rule set runs.
- No NVIDIA named profiles: the pinned validator release ships none (the
  CLI's `--profile` choices are empty), so gate 1 is the default rule
  set. No NVIDIA account, GPU or `uv` is needed — the judge installs two
  hash-pinned PyPI wheels with plain `pip --require-hashes`.
- The oracle checks properties, not provenance: any edit path that
  produces correct normals, extents, bindings and metadata passes —
  including the validator's own `--fix` flag where it applies.
- The geometry gate compares against `task/traffic_cone_broken.usda`:
  it pins mesh paths, point counts and the bbox to 1e-06 cm, so the
  repair must edit metadata/topology, never the points.
