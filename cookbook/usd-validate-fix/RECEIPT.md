## Deviations

Recorded, not hidden — the demo is judged against
`cookbook/DEMO-STANDARD.md`, and these points are open:

1. **No sandbox runs.** No `SBX_API_KEY` (or `E2B_API_KEY`) exists in this
   environment: `run.py` cannot create a sandbox, and a hand-set dummy key
   answers 401. So the receipt above is a *local* judge run, not the
   sandbox run `run.py` performs, and the standard's "Fresh-sandbox
   reproduction: two runs from two fresh sandboxes" section is **not
   satisfied** here.
2. **No independent reproduction.** `REPRODUCE.md` needs a second agent
   from a different model family in a fresh sandbox; that agent and a
   sandbox are both unavailable, so its table is empty by design.
3. **No real sandbox screen capture in the video, and no USD render.**
   See `media/STORYBOARD.md` deviations for the full list. In short: the
   pinned wheels ship no Hydra/hdStorm/UsdImaging renderer and no system
   OpenGL exists, so the video renders the asset's own points, topology,
   authored normals and bound-material colours with matplotlib (dumped
   unchanged by `media/extract_mesh.py`); the standard's "sped-up process
   run of the agent in the sandbox" slot is a 4x-speed replay of the
   judge's own measured verdict sequence, labelled as such on every frame.
4. **No blind review panel.** `media/REVIEW.json` is written with every
   judge slot pending and `pass: false`, because the two vision-model
   verdicts the standard asks for cannot be produced here. The video's
   caption-size, hook-content and storyboard rules are therefore unchecked
   by the panel; only `cookbook/tools/video_gate.py`'s mechanical file-level
   checks pass.
