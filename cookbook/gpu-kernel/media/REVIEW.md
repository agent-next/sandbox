# Reviewing the gpu-kernel demo media

All media in this directory is generated. Nothing is edited by hand; if
an output disagrees with the data, the data or the generator is wrong —
do not patch the PNG/MP4.

## Source data

| file | provenance |
|---|---|
| `data/gpu-run.log` | verbatim stdout of `python3 cookbook/gpu-kernel/run.py --gpu` on a 1 GiB RTX 5090 slice lease |
| `data/report.json` | the raw exec `report` dict from the same run, written by `run.py --gpu --report-json <path>` (good verdict incl. timing + per-mutant failed gates) |

`data/report.json` is produced only by a real GPU run. If it is absent,
`make_media.sh` exits non-zero with the command needed to produce it.

## Regenerating

```bash
bash cookbook/gpu-kernel/media/make_media.sh
```

- creates `media/.venv` (pinned `matplotlib==3.10.8`, `numpy==2.4.3`),
- requires `ffmpeg`, `ffprobe`, `node >= 18` and `npx` on PATH, plus
  Playwright's Chromium (render_clips.py) and Remotion's headless shell
  (`cd media/video && npx remotion browser ensure`),
- runs the judge for real in this sandbox and records it
  (`record_clips.py`), replays that capture to 30 fps footage
  (`render_clips.py`), assembles `video/src/data/scene.json`
  (`prepare_video_data.py`), composes the cut with Remotion
  (`media/video/`, headless Chrome) and encodes `demo.mp4` 1920x1080,
  30 fps, H.264 CRF 18 with ffmpeg,
- writes `MANIFEST.json`: sha256 of every output and of each output's
  source data.

ffmpeg only ever encodes — every pixel in `demo.mp4` is drawn either by
the recorded run or by the Remotion composition. Outputs (`*.png`,
`*.mp4`), `.venv/`, `.frames/`, `clips/` and `master/` are gitignored;
the manifest and this file are committed.

## Reviewer checklist

1. `data/` files unchanged since the lead's GPU run (`git log data/`).
2. `bash make_media.sh` exits 0 and rewrites `MANIFEST.json`; the
   recorded sha256s reproduce bit-for-bit on re-run with unchanged data
   (PNG/MP4 bytes are deterministic for fixed inputs and tool versions).
3. `result.png`: every `max_abs_err` point sits below the 1e-5 tolerance
   line; the GB/s label equals `2*4096*4096*4 / kernel_ms / 1e9`.
4. `loop.png`: one red cell per mutant row, and the red cell's gate name
   matches the `failed` list in `data/report.json` (11/11 killed).
5. `demo.mp4`: `ffprobe` shows 1920x1080, 30 fps, H.264 yuv420p, 25-60 s,
   <= 8 MiB, moov before mdat; `python3 cookbook/tools/video_gate.py
   media/demo.mp4` passes every check (it measures motion fraction, scene
   cuts and the static tail); every second before the end card is moving
   footage — the timing race, the row transform, the recorded sandbox run,
   the GPU timing or the proof HUD — never a still or a text-only frame.
6. `media/.venv/bin/python media/test_make_figures.py` passes.
7. the HUD's speed label and wall times come from `clips/racedata.json`,
   which is regenerated by each run, so they may legitimately differ
   between runs; the GPU-slice numbers come from the committed
   `data/report.json` and do not.

## Fail-loudly contract

`record_clips.py`, `prepare_video_data.py` and `make_figures.py` exit
non-zero and name the missing dotted field (e.g.
`good.verdict.timing.kernel_ms`) or required log line rather than
rendering a partial figure. `record_clips.py` additionally refuses to write
clips for a video unless the judge PASSes the known-good kernel and kills
every mutant in this run.
