# SPEC — `cookbook/scheduled-agent-digest/`

An agent builds the artifact for the job that runs while you sleep: a
scheduled sandbox wakes on a timer, digests yesterday's event log, posts a
summary, and pauses again — so nothing but the working minutes is paid for. A
judge it cannot fool decides whether the digest and the schedule are right.

## Goal

Produce **`digest.py`** (stdlib only) and a **`schedule.json`** describing one
nightly job, such that:

- for a given log date, `digest.py --log <events.csv> --date <YYYY-MM-DD>
  --out <file>` writes a JSON digest with exact daily aggregates;
- the aggregates are the truth for *that date's rows only*, and an empty
  selection produces a digest that says so instead of stale or fabricated
  zeros;
- the schedule fires the job at 02:00 local on a paused sandbox, resumes it,
  collects the digest, and pauses it again — and the record of three
  consecutive nights shows the sandbox paused between every pair of fires.

## The event log (input format)

A CSV file with header `ts,project,ms,code` and one row per request:

| column | meaning |
|---|---|
| `ts` | UTC instant, `YYYY-MM-DDTHH:MM:SSZ` |
| `project` | service name |
| `ms` | request latency in whole milliseconds |
| `code` | HTTP status code |

The judge ships its own fixtures, generated by `judge/make_fixtures.py` from
a fixed seed, so every number below is pinned and byte-reproducible. Nothing
is downloaded at grade time.

## Artifact

A directory (the path passed to `judge/grade.sh`) containing:

- `digest.py` — the digester, run as
  `python3 -I digest.py --log LOG --date DATE --out OUT`;
- `schedule.json` — the job description, an object with:
  - `"job"`: object with `"name"`, `"schedule"` (cron expression),
    `"command"`, `"timezone"`;
  - `"sandbox"`: object with `"pause_between_runs": true`;
  - `"steps"`: array of the run's steps, each an object with `"name"` and
    `"uses"` (one of `sleep_until_fire`, `resume`, `digest`, `collect`,
    `pause`).
- `judge/grade.sh` runs `digest.py` itself; the artifact is graded from what
  `digest.py` actually writes, never from what its comments claim.

`digest.py` writes `OUT` as one JSON object with exactly these keys:

| key | type | definition |
|---|---|---|
| `date` | string | the log date, echoed back |
| `status` | string | `"ok"` when ≥ 1 event was selected, `"no events"` when 0 |
| `events` | int | number of selected rows |
| `errors` | int | selected rows with `code >= 400` |
| `server_errors` | int | selected rows with `code >= 500` |
| `error_rate` | number | `errors / events`, 0.0 when there are no rows |
| `mean_ms` | number | mean latency of the selected rows, 0.0 when none |
| `p50_ms`, `p95_ms` | int | nearest-rank percentiles of the selected latencies, 0 when none |
| `max_ms` | int | slowest selected latency, 0 when none |
| `projects` | object | project → `{events, errors}`, sorted by key |
| `busiest_project` | string | the project with the most events, ties by name |

**Percentile rule (pinned):** nearest-rank — sort the selected latencies, then
take the value at 1-based index `ceil(q × n)`. For 128 events, p50 is index 64
and p95 is index 122.

**Empty-selection rule (pinned, the negative control):** when zero rows match
the date, `status` is exactly `"no events"` and every numeric field is 0 /
`{}` / `""`. A digest reporting `status: "ok"` with zeros, or any non-empty
`projects` map, fails.

## Canonical run (`judge/_night.py`)

The schedule is executed by the judge's own canonical runner, which is the
implementation the artifact's `schedule.json` must agree with:

```
sleep_until_fire -> resume -> digest -> collect -> pause
```

- `resume` and `pause` go through the **replaceable transport** in
  `judge/transport.py`: `paused_sleep` (the default) simulates the pause by
  sleeping, so the demo grades the *whole* lifecycle — including state
  transitions — without a cloud sandbox or a bill. `sbx_resume` /
  `sbx_pause` shims accept a client object whose `connect`/`pause` the judge
  drives with a fake, proving the shim wiring.
- `collect` copies the digest out and the run appends one line to the
  **run journal** `judout/run_journal.jsonl`, and writes `judout/state.json`
  — the sandbox state the judge reads between fires.

The artifact must not contain its own runner: `digest.py` digests, everything
else is the platform's. (A `run()` entry point in the artifact is allowed but
is not graded.)

## Judge gates (`judge/grade.sh <artifact> [--seed N] [--json out.json]`)

All gates are numeric and deterministic. Exit 0 only if every gate passes.
Each gate names its numbers.

| gate | what is checked |
|---|---|
| **G1 digest correctness** | for each fixture night (log dates 2026-10-12, 2026-10-13, 2026-10-14) every pinned field below matches the judge's independent oracle **exactly** |
| **G2 dates honoured** | the digest is built from the *selected date's* rows only: the pinned count of rows in the day is checked, and a mutant that totals the whole file (stale + tomorrow-morning rows included) must fail |
| **G3 json shape** | exactly the key set above, `projects` sorted by key, `error_rate == errors/events` to 1e-6 (the digest rounds to 6 dp), and the digest is valid JSON | 
| **G4 schedule spec** | cron fires at 02:00; job/zone/name present; `pause_between_runs` true; steps are exactly the five canonical steps in order |
| **G5 lifecycle** | three consecutive nightly fires, each producing a digest, with the sandbox state read as `"paused"` between every pair of fires and `"running"` during each |
| **G6 negative control** | the same `digest.py` on an empty log writes `status: "no events"` with all-zero numerics |
| **G7 failure identity** | a malformed row makes `digest.py` exit non-zero and writes nothing; no stale or partial digest is left behind, and the error names the log and the row |
| **G8 judge integrity** | the artifact under test cannot modify the judge: `judge/` checksums are compared before and after |

## Acceptance oracle (independent of "it ran")

The judge never trusts the artifact's arithmetic:

1. **Independent oracle.** The judge computes every aggregate itself — from
   the same fixture with a different implementation (a single sqlite3 pass
   over an imported table in `judge/_night.py`, where percentiles come from
   `ORDER BY ms LIMIT 1 OFFSET ceil(q*n)-1`, the *index arithmetic of the
   SQL result set*), and compares to the digest field by field. A digest that
   "looks plausible" but mis-computes a percentile, a rate, or the busiest
   project fails on a named field.
2. **Failure identity.** G7 runs the *same* `digest.py` on a log with a
   non-numeric latency and a short row: it must exit non-zero, name the file
   and the row, and leave no output file. A digester that crashes on the good
   logs but writes stale zeros on the bad one fails G1 before it is reached.
3. **Lifecycle state, not assertion.** The sandbox state between fires is read
   from the transport the judge drives, not from the artifact's
   `schedule.json` text.
4. **Fail-closed shape check.** A digest with an unknown key, a non-sorted
   `projects` map, or a payload that is not a JSON object fails G3, never
   passes with a warning.
5. **Reproducibility.** `make_fixtures.py` is deterministic; `grade.sh --seed
   N` twice produces byte-identical verdict JSON (checked by
   `selftest.sh`).

## Self-test (`judge/selftest.sh`)

- The known-good example in `examples/good/` passes every gate.
- ≥ 5 known-bad **single-edit mutants** generated by `judge/mutants.py`, each
  failing at least one gate. The eleven shipped:
  - `no-events-as-zero` — an empty log answered with `status: "ok"` and
    fabricated zeros (G6);
  - `all-rows-counted` — totals over the whole file instead of the selected
    date (G1 and G2; the verdict lists both);
  - `malformed-swallowed` — malformed rows skipped instead of rejected, so a
    bad log "succeeds" (G7);
  - `silent-no-output` — exits 0 without writing a digest (G1; the judge
    fails closed on the missing file instead of crashing);
  - `mean-unrounded` / `p95-off-by-one` (G1);
  - `error-rate-wrong` — a plausible-looking rate (5xx-only over events)
    instead of `errors / events` (G1 and G3);
  - `paused-skipped` — the schedule drops the pause step (G4);
  - `cron-hour-3` — the schedule fires at 03:00 (G4);
  - `busiest-tie-wrong` — the busiest project chosen by insertion order (G1);
  - `extra-key` — an extra digest field (G3).
- Every gate is covered by at least one mutant except G5 (lifecycle) and G8
  (integrity), which are exercised by the canonical run and the checksum
  comparison on every grade.
- Kill rate ≥ 90 % printed, and exit non-zero otherwise.
- Determinism: two `grade.sh --seed 1` runs produce byte-identical verdict
  JSON.

## Judge-integrity rule

The artifact under test is copied to a temp dir before grading; `grade.sh`
compares `sha256` of its own `judge/` tree before and after every grade and
fails closed if anything changed.

## Out of scope

- The digest's *presentation* (formatting, emoji, prose wording) beyond the
  pinned JSON fields.
- Any real cloud sandbox, real pause/resume, or the cost of one. The demo
  runs entirely on the local `paused_sleep` transport; the sbx shims are
  wired against a fake client and proven by the judge.
- Anything outside 2 vCPU / ~3 GB RAM: the whole grade is a few seconds.

## Tools (pinned by `judge/setup.sh`)

- **sqlite3 CLI 3.40.1-2+deb12u2** — the Debian bookworm package, downloaded
  from `deb.debian.org` and sha256-checked, providing the independent
  aggregate engine (`judge/_night.py`'s SQL oracle).
- **Python 3.10+**, standard library only: `digest.py`, the judge, the
  mutants, and the media pipeline.
- No tool is fetched with `latest`; nothing published in the last two weeks.
