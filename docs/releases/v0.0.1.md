First tagged release of the agent-next sandbox kit: disposable cloud Linux sandboxes (CPU and GPU) for coding agents.

## What is in it

- **Claude Code and Codex plugin** (`plugins/sandbox`, version 0.0.1): the hosted sandbox MCP server plus the `sandbox` skill. Tools: `sandbox_create`, `sandbox_exec`, files read/write, public preview URL, `sandbox_kill`.
- **`sbx` CLI** (`cli/`, version 0.0.1): `create`, `exec`, `list`, `kill`; GPU leases (`sbx gpu create/exec/pause/resume/kill/templates/info`); GitHub Actions runners on disposable sandboxes (`sbx runners image/serve/migrate/stats/debug`).
- **Cookbook** (`cookbook/`): example recipes for CFD, FEA, SPICE, PLC, QEMU firmware, GPU kernels, path tracing, MuJoCo, CAD, CI runners and browser tasks, many with committed receipts, plus the demo tooling (video gate, slop gate, result manifest).

## Install

```bash
claude plugin marketplace add agent-next/sandbox
claude plugin install sandbox@agent-next
python3 -m pip install "git+https://github.com/agent-next/sandbox@v0.0.1#subdirectory=cli"
```

If `sbx` is then not found, add the directory pip installed it to (`python3 -m site --user-base`/bin, or the interpreter's `bin/`) to `PATH`; see `cli/README.md`.

For the plugin, export `SBX_API_KEY`. The `sbx` CLI accepts `SBX_API_KEY` or `E2B_API_KEY`. The service also speaks the E2B API: for the official `e2b` SDKs, export `E2B_API_KEY` and `E2B_DOMAIN=sbx.agent-next.com` (or pass the key explicitly). Create sandboxes with `Sandbox.create()`, not the bare `Sandbox()` constructor:

```python
from e2b import Sandbox

sbx = Sandbox.create()
print(sbx.commands.run("echo hi").stdout)
sbx.kill()
```

## Fixed in the last round before tagging

Found by fresh agents testing the kit as first-time users, each in its own cloud sandbox:

- `sbx create`, the connect step of `sbx exec`, and `sbx kill` retry a 503 `restarting` reply up to three times, waiting `retry_after_s` clamped to 1-30 s; the command itself is never replayed (#101).
- Piping `sbx` output into a reader that closes early (`| head`) exits quietly instead of printing a traceback (#101).
- CLI README: what to do when `sbx` is not on `PATH` after install, how to reach a port through the public preview URL, the `runners migrate` / `runners stats` commands, and the CLI's exit codes (#101).
- Cookbook slop gate accepts the required `RECEIPT.md` / `REPRODUCE.md` and handles renames and non-UTF-8 paths (#99, #100).
- The plugin skill's GPU template examples now come from the live catalog (`gpu-lease-v06`, `mujoco`) (#102).

## Known limits

- The CLI is not published on PyPI; install it from the release tag as above.
- Lifecycle differs by client. MCP-created CPU sandboxes pause after the idle interval (300 s minimum) and resume on the next exec or files call. CLI-created sandboxes use kill-on-timeout: when the idle timeout expires, the sandbox and its files are deleted. REST clients: read `lifecycle.onTimeout` / `lifecycle.autoResume`; do not treat `end_at` alone as the pause deadline.
- There is no `sbx gpu list` yet; GPU leases show up in the plugin's `sandboxes_list` tool.
- The CLI has no CPU template listing yet: `GET https://api.sbx.agent-next.com/templates` (header `X-API-Key`) lists them (`agent-full`, `base`, `desktop`, `manim`, ...). GPU templates: `sbx gpu templates`.
- The CLI has no file copy command yet; use the plugin's files tools, or the `e2b` SDK with `E2B_DOMAIN=sbx.agent-next.com` (`files.read(path, format="bytes")` for binary files).
