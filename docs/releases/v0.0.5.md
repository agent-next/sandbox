Sandbox kit v0.0.5 improves CPU startup retries, GPU command guidance and release verification. It also adds an OpenAPI snapshot and recurring drift checks against the hosted API.

## What is new

- **CPU startup**: `sbx exec` and `sbx cp` retry a just-created sandbox that has not become visible yet (#132).
- **GPU commands**: `sbx exec` and `sbx cp` recognize GPU lease IDs and point to the GPU command; `sbx gpu create --wait S` waits up to 120 seconds for capacity (#136).
- **API contract**: a checked-in OpenAPI snapshot and daily drift check detect changes in schemas, complete media-type entries and unusual parameter identities (#124, #137, #139). Protected API links returning 401 are treated as reachable (#133).
- **Nightly verification**: the latest release is installed and exercised against the live service. Missing credentials fail with a JSON receipt, so an install-only check cannot close a live-service failure issue (#145).
- **Release tooling**: version bumps scaffold release notes, tag checks require them, and affected-test selection reduces PR verification time (#119, #130, #134, #135).

## Install

```bash
claude plugin marketplace add agent-next/sandbox
claude plugin install sandbox@agent-next
python3 -m pip install "git+https://github.com/agent-next/sandbox@v0.0.5#subdirectory=cli"
```

If `sbx` is then not found, put the interpreter's script directory on `PATH`:

```bash
export PATH="$(python3 -c 'import sysconfig; print(sysconfig.get_path("scripts"))'):$(python3 -m site --user-base)/bin:$PATH"
```

For the plugin, export `SBX_API_KEY`. The `sbx` CLI accepts `SBX_API_KEY` or `E2B_API_KEY`. The service also speaks the E2B API: for the official `e2b` SDKs, export `E2B_API_KEY` and `E2B_DOMAIN=sbx.agent-next.com` (or pass the key explicitly). Create sandboxes with `Sandbox.create()`, not the bare `Sandbox()` constructor:

```python
from e2b import Sandbox

sbx = Sandbox.create()
print(sbx.commands.run("echo hi").stdout)
sbx.kill()
```

## Known limits

- The CLI is not published on PyPI; install it from the release tag as above.
- Lifecycle differs by client. MCP-created CPU sandboxes pause after the idle interval (300 s minimum) and resume on the next exec or files call. CLI-created sandboxes use kill-on-timeout: when the idle timeout expires, the sandbox and its files are deleted. REST clients: read `lifecycle.onTimeout` / `lifecycle.autoResume`; do not treat `end_at` alone as the pause deadline.
- Export `SBX_API_KEY` before the first Claude Code session that loads the plugin. A session started without it gets the server's OAuth challenge, which Claude Code caches: the sandbox server then shows `needs-auth` (no sandbox tools, also in headless `claude -p`) even after the key is exported, while `claude mcp list` may still say Connected. To recover, follow "API key" in the [plugin README](https://github.com/agent-next/sandbox/blob/main/plugins/sandbox/README.md#api-key): it clears only the sandbox server's cached entries, then start a new session. Alternatively, pass the server explicitly:

  ```bash
  cat > sbx-mcp.json <<'EOF'
  {"mcpServers": {"sandbox": {"type": "http", "url": "https://api.sbx.agent-next.com/mcp/v1", "headers": {"X-API-Key": "${SBX_API_KEY}"}}}}
  EOF
  claude -p --mcp-config sbx-mcp.json "..."
  ```
- `sbx cp` copies one file per call; directories are not supported.
- A connection timeout during `sbx cp` is reported as a `--timeout` deadline too; check the network first if a small file times out.

- Nightly live checks require the `SBX_SMOKE_KEY` repository secret. Without it the nightly gate fails; a local keyless installation check does not establish live readiness.
- Cookbook videos have not all passed the current media acceptance standard; consult each demo's receipts and limits before using it as a reference.
